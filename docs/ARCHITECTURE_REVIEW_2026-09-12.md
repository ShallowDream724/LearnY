# build 26 架构评估

## 当前判断

综合评分 **8.0 / 10**。这是基于当前源码、职责边界和本轮实际修复的工程判断。项目已具备适合长期维护的基础，距离非常优秀仍有明确的改进空间。

已做好的部分：

- 认证协议、选课目录、教学日期、课表投影、缓存、同步及页面已有明确职责。课表的整学期共享请求、账户隔离、权威空日及缓存升级都在数据层完成。
- 首页、作业总览、课程详情、文件列表使用共用业务动作。本轮删除课程详情独立的成绩布局／状态判断／百分制色彩阈值，统一文件图标和长按动作，修复了“共享同一数据却呈现不同结果”的退化。
- 性能约束具体落在代码里：课表查询合并，列表惰性构建，壁纸解码／输出有尺寸上限，滚动背景通过重绘信号更新，不逐帧重建整页。

仍需改进的部分：

- `lib/core/api/learn_api.dart` 仍约 2,249 行，包含较多学校协议与兼容分支，后续应继续按实际协议职责拆分，并减少不再使用的兼容面。
- 部分动作直接依赖 Riverpod `Ref`，其中收藏操作同时协调本地仓储与远程接口，独立测试和跨入口编排仍可进一步改善。远程收藏失败目前保留本地结果并写诊断日志，缺少用户可辨认的待同步状态。
- 跨作用域取消主要保证旧结果不写入；部分底层 HTTP 仍可能继续运行。物理取消、统一错误分类和业务命令层还有收敛空间。

发布 CI、真实多端交互验收和性能测量属于工程成熟度的后续工作。当前评分不包含尚未完成的全路径性能基准或 iOS 验收。

## 手机与电脑的代码共用

按 Git 工作区中的自有源代码统计（排除 `.g.dart`、`.freezed.dart`、生成插件注册代码；不计资源、构建配置、测试和第三方库）：

| 源码区域 | 规模 | 职责 |
| --- | ---: | --- |
| `lib/` 手写 Dart | 约 5.2 万行，约 240 个文件 | 业务、数据、主要界面与响应式适配 |
| Android 自有 Kotlin | 29 行，1 个文件 | 校园认证 Cookie 原生桥接 |
| Windows runner C++ / 头文件 | 691 行，8 个文件 | 窗口、Flutter 承载与系统启动 |

Dart 约占以上源代码行数的 **98.6%**。这是源码分布指标，不能等同于“98.6% 的运行路径完全共用”：Dart 内仍包含平台判断、触控／鼠标分支和布局适配。

Android 和 Windows 使用同一个 Flutter 入口、业务模块、数据库与大部分页面组件。高共用比例主要来自 Flutter；行为一致性则依赖清楚的组件和动作边界。此前课程详情的重复成绩实现说明，源码共用比例很高时仍然会出现架构退化。本轮通过删除重复实现、统一入口契约和验证关键行为改善了这一点。

适配层继续负责合理差异：手机的滑动／长按，桌面的侧栏／右键，原生认证 Cookie 及系统文件能力。布局按内容宽度调整，业务状态与成绩解释保持同源。
