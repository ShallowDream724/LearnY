# LearnY 设计体系

## 产品基准

LearnY 是每天反复使用的学习工具。一次打开应迅速知道当天的安排、需要处理的作业，以及新到的课程资料。完整任务包括进入、辨认、操作、等待、完成和返回；各环节共同决定体验质量。界面的精致来自这些环节协同成立，包括动作的范围清楚、内容真实、操作及时响应、退出后仍能继续刚才的事。

参考 Emil Kowalski skills 的全部 12 份指南与 7 份配套文档。具体来源、适用条件与实现草稿的复审项见 [设计资料研读](DESIGN_REFERENCE_REVIEW.md)。参考其信息组织、即时反馈、空间关系、可打断过渡、合理默认值与细节一致性；Web 渲染规则、指定库和物理参数按 Flutter 重新评估。

本文件描述已确认的产品要求与设计方向，不代表整个界面已经实现并验收。2026-09-07 的 UI 重塑草稿仍待整合，不能以换过颜色、圆角或加入共享组件作为完成依据。

## 信息与布局

- 导航、当前学期和同步状态属于应用上下文。学期选择明确影响范围；同步应自动完成，必要的手动刷新放在其作用范围能被理解的位置。不能仅为容纳控件而增加常驻横栏或侧栏区域。
- 首页保持每日课表入口，独立周窗口不更改首页学期或日期。跨学期规则遵循 SCHEDULE_DESIGN.md。
- 宽屏利用并列区域缩短阅读和返回路径；窄屏按任务重要性纵向组织。布局依据扣除侧栏等区域后的实际可用宽度，操作入口依据鼠标、键盘和触控能力。窗口缩放、平板旋转与大字号仍须保持任务路径。
- 空数据不展示没有决策价值的零值统计。筛选结果为空时保留筛选入口；整个学期为空时给出学期上下文。请求失败不等同于空数据。
- 列表、正文与阅读器按内容分别确定密度和阅读宽度。长文需要受控行长，文件列表需要扫描与比较，课表需要时间位置关系，不能用同一最大宽度代替判断。页面区域用间距和分隔组织，独立重复项目才使用卡片。禁止装饰性左侧竖条。

## 完整任务

| 场景 | 首要信息与操作 | 连续性与状态要求 |
| --- | --- | --- |
| 首页 | 当天时间、地点、下一步待办 | 每日课表保持紧凑；少课不撑高，密集数据不挤掉其他学习任务 |
| 周课表 | 一周安排、切周、局部学期、回到当前时间 | 独立浏览范围；支持便捷退出；取消跨界确认留在原周 |
| 作业 | 需要处理什么、截止时间、提交状态 | 空学期不保留无意义零值大统计；筛选为空仍可解除筛选；提交反馈必须反映真实结果 |
| 课程与详情 | 课程身份、通知、作业与资料 | 打开和返回保留列表位置、查询与范围；长标题和元数据有明确换行策略 |
| 文件与阅读 | 文件身份、可用内容、当前主要动作 | 下载进度、缓存、失败恢复有连续状态；不在不同位置重复同一组工具 |
| 搜索 | 查询、结果分组、定位内容 | 快速改词不被旧响应覆盖；离开详情回来保留查询与位置 |
| 登录与设置 | 完成登录、必要的个人选择 | 校园服务会话自动协调；人工验证按真实需要出现；常规技术细节不成为用户任务 |

该表约束任务关系，不冻结最终布局，也不新增尚未确认的业务功能。

## 视觉与输入

- 安静的基础材质让主要操作和内容突出。当前草稿尝试中性色与蓝色操作强调，具体色值仍需在真实内容和浅深主题中确认。颜色按语义角色定义；暗色界面不能机械复用浅色选中色。提醒、失败、成功与课程区分各有实际含义。
- 文字靠字号、字重、行距和对比建立主次。中文、时间和数字共同排版，不以淡小字掩盖重要信息。时间、计数的更新不应引起横向跳动；字体放大时布局能重新排布，不能只缩小文字或截断关键内容。
- 按钮和可点击项目提供可辨认的按压、悬停、焦点、禁用状态。按下立即反馈，普通动作在有效抬起后执行，移开可取消。反馈可用状态层或其他合适方式，不要求所有项目缩放。图标操作有提示；常用功能不能只藏在长按或滑动中。
- 弹层支持明确的退出路径，保留触发位置或浏览上下文。鼠标菜单、对话框和大课表各自采用合适的层级与遮罩；嵌套弹层的关闭顺序明确。键盘焦点可进入、可返回；减少动态效果时可采用清楚的静态反馈。
- 材质用来解释层级：浮在内容之上的工具可以有适当半透明，普通页面无需装饰性毛玻璃。遮罩、阴影、边缘和文字对比应协同；深色、繁杂背景与低性能设备都要能成立。

## 动效与状态

- 页面切换与状态变化立即响应，过渡不阻塞合理的下一次操作。高频列表不逐项延迟出现。可中断元素从当前屏幕位置继续，手势松开时依据实际场景传递速度；不能从已经过时的逻辑端点重新播放。
- 动效按用途选择：按压反馈、内容替换、导航、弹层、直接拖动具有不同的时序和生命周期。`AppMotion` 的草稿常量只可视为普通场景起点，不构成全部动效的规格。
- 同一个操作的反馈保持连续。下载或同步已经在原位显示状态时，避免又堆叠多条提示；完成、取消与失败有不同结果。防止重复提交由业务操作状态负责，不能用转场期间锁住整个界面代替。
- 本地正在看什么与后台正在请求什么有明确所有权。切学期、换账号或更新搜索后，旧请求不能覆盖新范围；重试与后台更新尽量保留仍有用的内容。
- 加载中、成功无数据、筛选无结果、暂时离线、缓存过期和请求失败需要不同恢复路径。课表来源与不确定时间继续遵守 [课表设计](SCHEDULE_DESIGN.md)，不能用美化后的统一空态抹平这些差异。

## 实现与验收

共用颜色、字体、输入组件与基础呈现放在 `lib/core/design`；导航与响应式外壳放在 `lib/core/shell`；页面组合内容并绑定业务动作。认证、同步、学期和提交继续由业务模块负责。共用组件封装真实重复的行为，不把每种空态、列表或弹层硬塞进一个不断增加布尔开关的万能组件。

先把完整任务与关键状态在真实 Flutter 界面里做通，再把经得起使用的共性收敛为组件，逐步推广到其他页面。跨页面改动需在信息密度和返回行为上一起审视，不能靠各页分别换样式完成整合。

必要验证包括受影响的业务边界、静态检查，以及少量实际 Flutter 布局与交互预览。真实校园会话、设备手感与实际提交由项目负责人验收。不得把 HTML 原型或模拟数据截图称为真实业务验证；已验证单元及时提交，未完成的 UI 草稿不包装成发布版本。
