# LearnY 设计体系

## 产品基准

LearnY 是每天反复使用的学习工具。一次打开应迅速知道当天的安排、需要处理的作业，以及新到的课程资料。完整任务包括进入、辨认、操作、等待、完成和返回；各环节共同决定体验质量。界面的精致来自这些环节协同成立，包括动作的范围清楚、内容真实、操作及时响应、退出后仍能继续刚才的事。

参考 Emil Kowalski skills 的全部 12 份指南与 7 份配套文档。具体来源、适用条件与应用记录见 [设计资料研读](DESIGN_REFERENCE_REVIEW.md)。参考其信息组织、即时反馈、空间关系、可打断过渡、合理默认值与细节一致性；Web 渲染规则、指定库和物理参数按 Flutter 重新评估。

本文件描述已确认的产品要求与设计方向。2026-09-07 已整合首页、作业、课程、文件、搜索、登录与设置的界面及共享交互；真实 Flutter 预览与必要行为检查补充集成证据，设备手感和学校服务仍由项目负责人验收。后续 PDF/PPT 阅读能力与 AI 工具接口单独迭代。

## 信息与布局

- 导航、当前学期和同步状态属于应用上下文。学期选择明确影响范围；同步应自动完成，必要的手动刷新放在其作用范围能被理解的位置。不能仅为容纳控件而增加常驻横栏或侧栏区域。
- 首页保持每日课表入口，独立周窗口不更改首页学期或日期。跨学期规则遵循 SCHEDULE_DESIGN.md。
- 宽屏利用并列区域缩短阅读和返回路径；窄屏按任务重要性纵向组织。布局依据扣除侧栏等区域后的实际可用宽度，操作入口依据鼠标、键盘和触控能力。窗口缩放、平板旋转与大字号仍须保持任务路径。
- 空状态不展示没有决策价值的占位信息。筛选结果为空时保留筛选入口；整个学期为空时给出学期上下文。请求失败不等同于空数据。目录中的资料总数可保留零值，按具体浏览任务判断。
- 列表、正文与阅读器按内容分别确定密度和阅读宽度。长文需要受控行长，文件列表需要扫描与比较，课表需要时间位置关系，不能用同一最大宽度代替判断。页面区域用间距和分隔组织，独立重复项目才使用卡片。禁止装饰性左侧竖条。

## 完整任务

| 场景 | 首要信息与操作 | 连续性与状态要求 |
| --- | --- | --- |
| 首页 | 当天时间、地点、下一步待办 | 每日课表保持紧凑；少课不撑高，密集数据不挤掉其他学习任务 |
| 周课表 | 一周安排、切周、局部学期、回到当前时间 | 独立浏览范围；支持便捷退出；取消跨界确认留在原周 |
| 作业 | 需要处理什么、截止时间、提交状态 | 逾期单独分组；筛选为空仍可解除；提交页截止时间常驻，要求正文可折叠；成功回执主动退出，未保存修改退出前确认 |
| 课程与详情 | 课程身份、通知、作业与资料 | 打开和返回保留列表位置、查询与范围；长标题和元数据有明确换行策略 |
| 文件与阅读 | 文件身份、可用内容、当前主要动作 | 下载进度、缓存、失败恢复有连续状态；不在不同位置重复同一组工具 |
| 搜索 | 查询、结果分组、定位内容 | 分组菜单过滤结果；请求错误可重试，空结果可改词；快速改词不被旧响应覆盖；离开详情回来保留查询与位置 |
| 登录与设置 | 完成登录、必要的个人选择 | 校园服务会话自动协调；人工验证按真实需要出现；常规技术细节不成为用户任务 |

该表约束任务关系，不冻结最终布局，也不新增尚未确认的业务功能。

## 视觉与输入

- 明亮的淡靛底色与白色内容表面，深色采用有色相的深蓝灰底层。靛蓝承载操作，课程使用稳定的柔和色彩身份；提醒、失败、成功单独表达状态。应用标识采用已确认的日晷原稿，Windows、Android、登录和侧栏使用同一身份；原稿与导出方式见 [品牌资源](../tool/brand/README.md)。颜色通过主题与 `StudyPalette` 定义，不在各页复制调色盘。
- 文字靠字号、字重、行距和对比建立主次。中文、时间和数字共同排版，不以淡小字掩盖重要信息。时间、计数的更新不应引起横向跳动；字体放大时布局能重新排布，不能只缩小文字或截断关键内容。
- 应用声明简体中文区域并使用 Flutter 官方中文本地化。两端随包内置未经修改的霞鹜文楷 GB 屏幕阅读版；屏幕版本身已增强笔画，不再靠大量粗体建立层级。主题和独立文字样式共用 `AppFont` 与 `AppTypography`；来源、版本和许可证见 `assets/fonts/README.md`，应用设置提供开源许可入口。原始字体完整保留，避免课程、人名或通知中的字符因子集化缺失。
- 真实选择、悬停、按压与焦点分别呈现。选中导航或筛选保留明确的前景与表面区别，普通行使用克制的反馈。设置由整体分组面板承载，行内有独立水平内边距与分隔；外观控件位于行尾。鼠标关闭外观菜单后不保留焦点填色，键盘关闭后保留原控件焦点。自动登录的完整诊断收进详情，常规页面保留摘要、开关和恢复入口。
- 按钮和可点击项目提供可辨认的按压、悬停、焦点、禁用状态。按下立即反馈，普通动作在有效抬起后执行，移开可取消。反馈可用状态层或其他合适方式，不要求所有项目缩放。图标操作有提示。手机列表的已读操作仅由未读项左滑触发，不放置常驻按钮；已读项目可从详情恢复未读。桌面每行左侧只有一个已读/未读按钮，以信封表达阅读状态，不使用容易误解为任务完成的对号；通知的重要标记保留在内容右上角。不以鼠标拖动模拟左滑。
- 弹层支持明确的退出路径，保留触发位置或浏览上下文。鼠标菜单、对话框和大课表各自采用合适的层级与遮罩；嵌套弹层的关闭顺序明确。键盘焦点可进入、可返回；减少动态效果时可采用清楚的静态反馈。
- 材质用来解释层级：浮在内容之上的工具可以有适当半透明，普通页面无需装饰性毛玻璃。遮罩、阴影、边缘和文字对比应协同；深色、繁杂背景与低性能设备都要能成立。

## 动效与状态

- 页面切换与状态变化立即响应，过渡不阻塞合理的下一次操作。高频列表不逐项延迟出现。可中断元素从当前屏幕位置继续，手势松开时依据实际场景传递速度；不能从已经过时的逻辑端点重新播放。
- 动效按用途选择：按压反馈、内容替换、导航、弹层、直接拖动具有不同的时序和生命周期。`AppMotion` 的常量只可视为普通场景起点，不构成全部动效的规格。骨架与页面过渡遵循减少动态效果设置。
- 同一个操作的反馈保持连续。下载或同步已经在原位显示状态时，避免又堆叠多条提示；完成、取消与失败有不同结果。已读操作立即保存，未读列表以淡出与高度收拢承接数据移除，手机保留左滑位置并提供一次轻触觉反馈。每个列表共用一行内联结果与撤销入口，连续操作合并计数；不逐条弹出成功提示，不抢焦点，不阻塞其他条目。最后一项退出后再显示空态，撤销入口继续保留。减少动画时仍保留静态结果反馈。防止重复提交由业务操作状态负责，不能用转场期间锁住整个界面代替。
- 本地正在看什么与后台正在请求什么有明确所有权。切学期、换账号或更新搜索后，旧请求不能覆盖新范围；重试与后台更新尽量保留仍有用的内容。
- 加载中、成功无数据、筛选无结果、暂时离线、缓存过期和请求失败需要不同恢复路径。课表来源与不确定时间继续遵守 [课表设计](SCHEDULE_DESIGN.md)，不能用美化后的统一空态抹平这些差异。

## 实现与验收

### 构图与几何

- 首页宽屏以 5:3 的内容区域分配日程/待办与通知/文件；窄屏保持每日课表、待办、更新的阅读顺序。这个比例服务于各列实际信息，并非通用比例模板。日程保留紧凑的日视图，日期与控制集中在同一标题区，单门课使用横向内容关系，不嵌套一张填满大面板的空卡。
- 课程卡片使用淡彩玻璃与课程图形：标题占完整行宽，教师右侧安排图形，身份区与统计区之间保留细分隔。待交、未读按真实状态显示，资料数量保留零值，避免同组卡片因统计缺失而失去排列关系。外边距保护文字，同排高度按真实内容与操作区测量，宽卡不按固定宽高比增高。课程颜色与课表同源，图形库、自选流程与默认匹配遵循 [课程图形规范](COURSE_ICONS.md)。
- 作业、文件与搜索控制阅读宽度。作业右侧优先呈现结果：数值成绩使用突出字号并附“已批改”，其他情况直接显示提交状态，不猜测总分。桌面标题、日期、结果保持稳定列关系；手机将日期放在标题下，结果保留右侧；窄屏或大字号时移到下方右侧，避免挤压标题。未提交项目可点击状态、长按或右键调整本地提醒，不常驻重复的更多按钮。信息密集的列表不使用大面积装饰阴影，独立面板使用一致的边缘、填色与轻微光影。
- `StudySurface` 负责通用面板与可选交互，不决定业务状态或列表几何。课程页的 `CourseGlassBackdrop` 与 `CourseGlassSurface` 独立负责共享背景、玻璃内面和边缘：保留已确认的周边光感，内面清澈、透色轻微，避免用明显不同的卡片亮度制造视觉差异。绘制位置随滚动和缩放更新，不逐卡片进行布局后测量，不叠加背景模糊。键盘、指针和触控反馈沿用 Flutter 的语义与输入机制。

留白必须能解释内容关系。标题与边界之间的呼吸空间、不同任务之间的间隔，与固定高度剩下的空洞不是同一件事。字库、字号、行高、内边距与真实内容一起决定几何；单独换色或增加圆角不能证明整页成立。

共用颜色、字体、输入组件与基础呈现放在 `lib/core/design`；导航与响应式外壳放在 `lib/core/shell`；页面组合内容并绑定业务动作。认证、同步、学期和提交继续由业务模块负责。共用组件封装真实重复的行为，不把每种空态、列表或弹层硬塞进一个不断增加布尔开关的万能组件。

先把完整任务与关键状态在真实 Flutter 界面里做通，再把经得起使用的共性收敛为组件，逐步推广到其他页面。跨页面改动需在信息密度和返回行为上一起审视，不能靠各页分别换样式完成整合。

必要验证包括受影响的业务边界、静态检查，以及少量实际 Flutter 布局与交互预览。真实校园会话、设备手感与实际提交由项目负责人验收。不得把 HTML 原型或模拟数据截图称为真实业务验证；已验证单元及时提交，未完成的 UI 草稿不包装成发布版本。
