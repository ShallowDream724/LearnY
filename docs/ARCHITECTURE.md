# 当前架构与边界

本文件记录已经实现的结构。旧的 blueprint 文件是设计参考；尚未落地的设想以路线图为准。

build 26 的架构评分、证据、剩余改进及跨平台源码统计见 [2026-09-12 架构评估](ARCHITECTURE_REVIEW_2026-09-12.md)。

## 平台与业务

- `lib/core/api` 封装网络学堂协议、身份认证和 API 数据模型。
- `LearningReadApi` 是学期、同步和课表的读取接口，由真实客户端实现；这些业务服务不依赖完整的认证与 Dio 客户端。
- `lib/core/database` 用 Drift 保存本地课程、通知、作业、文件与应用状态。
- `lib/core/semester` 管理学期目录、身份解析和选择入口。
- `lib/core/schedule` 管理课表模型、日期投影、缓存协议和课表仓储，独立于首页组件及 Riverpod。
- `lib/core/courses` 管理权威选课集合，供全局同步和课表日期浏览共用。
- `lib/core/sync` 将服务端快照更新到本地库；`SyncNotifier` 负责队列、超时、冷却与状态发布。
- `lib/features` 按课程、作业、文件、搜索等用户任务组织界面及相应业务控制器。
- `lib/core/design` 和 `lib/core/shell` 提供共用视觉基础、尺寸适配和输入方式适配。
- `lib/core/wallpaper` 分离自定义背景的裁剪几何、受限图像解码／导出和文件持久化；裁剪界面与偏好 Provider 不自行处理文件布局。
- `lib/demo` 通过依赖替换驱动相同的应用流程，不访问正式账户或学校服务。

Android 和 Windows 共用 Dart 业务逻辑、数据库协议与主要界面。`android/` 与 `windows/` 负责系统启动、插件与打包。Windows 主界面由 Flutter 绘制；WebView2 用于学校统一登录，不承载应用主界面。Android 的窄原生接口补齐认证 HttpOnly Cookie 读取。尚未引入 `fluent_ui`。

## 学期状态

`serverCurrentSemesterId` 表示学校确认的当前学期，`currentSemesterId` 表示用户正在浏览的学期。两者独立持久化，普通同步不得覆盖用户选择。首次无选择时采用学校当前学期；启动恢复优先使用已保存的选择。

`currentTeachingSemesterIdProvider` 根据上海日期与已核验校历确定当前教学学期，供选择器标记；`serverCurrentSemesterId` 的标记明确为「网络学堂当前学期」，不能代表已经开课。2026 年夏季范围包含 9 月 13 日周日，秋季从 9 月 14 日开始。首页标题始终显示正在浏览的学期；校历跨日、学堂提前开放新学期均不覆盖用户已选范围。没有可靠教学边界时不标记当前教学学期。

目录刷新合并学校的学期列表和当前学期详情，保留历史学期已知的日期。某一接口失败时使用其余结果，并向界面报告部分失败。目录数据来自服务端及本地缓存，不凭空构造下一学期。

切换通过 `SyncNotifier.selectSemester` 执行：使旧同步任务失效，串行地以事务保存选择，更新界面作用域，再刷新最后选定的学期。本地缓存可以立即浏览。搜索会废弃旧查询结果并加载目标学期语料。登录、退出登录的持久化操作也串行执行，只有最后一次有效操作可以发布认证状态。

认证控制器与会话仓储的生命周期不依赖账户代次下的 API 客户端。仓储通过延迟解析的远程退出回调使用当前客户端，避免登录/退出更新 `dataSessionEpoch` 时销毁正在执行操作的控制器。远程退出只提交一次、不跟随登录重定向，五秒后取消未完成请求；远程失败仍继续本地身份、凭据和 Cookie 清理。

教务日历接口按绝对日期查询，没有学期参数。课表可独立浏览过去或未来的自然周。学习内容按所选学期隔离；课表由 `AcademicCalendar` 查明日期所属学期，再读取该学期课程目录并补全唯一匹配的详情链接。教学边界只采用经过 `AcademicCalendarSource` 加载、校验的校历，不能采用 Learn 启用日期；当前来源为带出处、核验日和学生类别的 JSON 资产。未知边界不推算，详见 [ACADEMIC_CALENDAR.md](ACADEMIC_CALENDAR.md)。日历返回结果不写入学习内容表。

## 课表职责

- `schedule_models.dart` 定义日期、课程安排和加载结果，区分已取得课表数据、尚无缓存、正在更新和请求失败。确认空数组会结束加载，不能把请求失败视为无课。
- `semester_schedule_cache.dart` 负责网络学堂排课解析和复现，不再持久化第二份课程目录；旧序列化器已删除。`schedule_projection.dart` 负责日期映射和来源合并；`schedule_cache_codec.dart` 以 v3 保存来源、时长可信度和教务权威日期集合，兼容 v1/v2 历史记录。旧教务缓存首次读取即从查询范围恢复覆盖，迁移写入仍受事务和账户取消检查保护。
- `ScheduleRepository` 注入读取接口、数据库、时钟、学期边界和课程目录仓储，负责缓存优先、远程刷新、取消检查及事务写入。教务快照以 `calendar-v2` 日期作用域与周一为键，独立于学习学期选择；更换账户会清理全部周缓存。旧版单窗口缓存仍可在日期完全匹配时读取。
- `CalendarRangeRepository` 归账户所有，已知单学期范围一次读取整学期并事务保存每周快照。同学期视图共享传输和新鲜期，切周取消视图不取消正在回填的整学期任务；账户释放才使传输失效，失效事务不写缓存或失败记录。未知或跨多个学期的自然周保持按周读取。
- 教务 HTTP 请求独立控制超时；日期请求等待共享校园会话恢复，不再用 20 秒总期限截断认证链。失败后有缓存时退避 2 小时，无缓存时退避 1 分钟，成功刷新间隔 12 小时。共享传输额外保留一分钟完成结果，避免相邻视图同时排队。课程目录有 15 分钟新鲜期。手动刷新重置相关学期教务（未知范围重置本周）及课程目录的新鲜期。
- 教务成功查询覆盖的日期完全以教务为准，空日和空周也禁止排课推算补课；仅未确认日期可使用注明来源的推算。学期边界周仅标记教学范围内日期。已确认退课的名称索引过滤当前及未来的滞后教务数据，历史教务快照保留。推算不会越过学期结束日期。
- `scheduleWeekProvider` 组装账户和自然周，同周共享数据，与学期选择独立。`homeScheduleBrowseDateProvider` 将首页所选学期和日期映射到可浏览范围；默认日期随上海时间跨日更新，到学期末日停住。主动选定的日期保持不变，首页换学期重置日期定位。作用域结束取消旧操作。
- `ScheduleBrowser` 只负责每日课程；`ScheduleDialog` 提供独立周弹层，`WeeklyTimetable` 按共享时间轴绘制完整课表。来源提示和待安排提醒共用 `ScheduleNotes`。具体呈现见 [SCHEDULE_DESIGN.md](SCHEDULE_DESIGN.md)。
- `ScheduleSemesterNavigation` 只负责学期边界、相邻学期和初始日期策略；`SchedulePager` 提供有边界的日/周页面，外滑手势单次触发确认。首页由 `HomeTodayScheduleSection` 在用户确认后调用全局学期切换；周弹层的选择只保存在自身状态。`showSemesterPicker` 仅返回选择结果，由调用者决定作用域。

每日方向键按天移动，桌面另有前后按钮；手机省去按钮并保留跨日滑动。日期直接作为首页课表标题，两处都支持日期选择与回到今天。周弹层按周移动，可用外部空白、关闭按钮或 Esc 退出。首页顶栏刷新与下拉刷新共用同一动作和完整忙碌周期，覆盖学习内容及课表，避免局部成功冒充全部完成；周弹层保留局部刷新。

宽布局把学期选择、刷新和同步错误入口放到侧栏；窄布局的学期入口嵌入页面 AppBar 标题，不再增加独立横栏。首页保留问候、统计与紧凑每日课表；宽屏在其下并列待办和更新，窄屏顺序排列。分钟时钟订阅取消或暂停时立即释放计时器；合并流同时启动各来源的取消，避免慢数据源阻塞其他来源清理。

`RegistrarCalendarApi` 处理教务票据、HTTPS OAuth/WebVPN 重定向、GBK 页面及 JSONP；教务连接失败不会使网络学堂登录失效。正常登录的 ticket 和 fallback 路径均通过 `CampusCookieBridge` 将统一身份 Cookie 交给 API，并清除上次身份的教务、OAuth 和 WebVPN 会话。Windows 与 Android 可导出 HttpOnly Cookie，课表没有独立授权页或授权按钮。

`IdentityAuthApi` 共用身份表单、可信设备登录与 SM2 加密协议，串行加载和提交身份表单。教务优先沿当前校园 Cookie 完成重定向；确实遇到身份登录表单时，才使用已启用的自动登录凭据为该服务续期，继续受限的回调链。可信设备快捷登录被退回登录表单时，可继续一次账号密码登录；一条恢复链最多提交一次密码，同一 API 客户端的学堂和教务共用每账号一分钟的密码提交限流，不循环尝试。此路径不依赖网络学堂会话过期，也不通过再次登录网络学堂冒充教务恢复。

`Learn2018Helper` 持有一个长期使用的 `RegistrarCalendarApi`，不同日期请求串行使用同一校园会话；成功后的新日期请求直接查询日历，不重复获取票据或登录。实际授权失效才重新建立直连/OAuth/WebVPN 路由。限流返回独立的 `recoveryDeferred`，当前请求在队列内等待后最多再尝试一次，不将限流宣称为人工验证。最新请求负责发布校园验证状态；显式登录/账户代次变化会重建 API 客户端，旧客户端不能再修改验证横幅。网络变化本身不触发密码提交，仍以学校响应为依据。

`AuthEntryCoordinator` 在发布登录成功前调用 `CampusLoginContinuation` 建立校园访问会话。Cookie 读取失败不能清除已有会话或假装传递完成；教务暂时不可用不阻塞学堂登录。学校确实要求人工验证时，在同一认证 WebView 中继续，浏览器完成后自动传递 Cookie 并返回，无需“验证并返回”。已登录后的人工验证需求使用应用现有的重新登录入口；`campusIdentityVerificationRequiredProvider` 独立于学堂会话健康状态，避免把正常学堂会话标成过期。取消登录不发布成功，更换身份时清除旧身份的自动恢复凭据。日历接口返回空数组只表示本次未返回事件，不构成发布状态或完整认证状态的证明。

启用自动重新登录后，校园接续优先使用刚保存的凭据执行受限的自动恢复。需要网页交互时，`RegistrarException.browserEntryUri` 保留实际经过的 WebVPN/OAuth 入口；浏览器从该入口建立自己的 OAuth 会话，不直接沿用 API Cookie 环境产生的身份表单地址。浏览器到达服务页后统一导出身份、OAuth、WebVPN、教务四个域的 Cookie，再以 Cookie 验证校园访问。接续不再用独立十二秒总超时放弃仍在运行的认证请求；各 HTTP 请求仍保留传输超时。

## 网络学堂会话恢复

`Learn2018Helper` 除统一身份认证页和 HTTP 401/403 外，还识别网络学堂在原请求地址返回的 HTTP 200 登录超时页，以及登录错误面板中的 401/403。确认为会话失效后才调用 `SessionRecoveryCoordinator`，先尝试 SSO Cookie，再使用用户已启用的安全凭据重新登录，刷新 CSRF 后只重试原请求一次。普通连接超时或服务端 500 不触发密码提交。

首次 CSRF 获取与会话恢复分别合并并发请求；迟到的旧会话响应复用已恢复的 CSRF。登录和会话探测共用 API 传输配置，逐跳保存 Cookie，并复用最终认证页的 CSRF，避免成功登录后再次请求超时。同步失败后切回应用、网络重新可用或网络类型变化会重新尝试；已过期的会话不受正常后台刷新十分钟间隔限制。

校园身份成功页支持 OAuth 主机上的 `/thu-oauth/callback`。教务 HTTP 200 的 `/sso_fail.jsp` 和 `/timeout.jsp` 是授权失败，最多更新一次服务票据，不用新密码提交替代票据恢复。启用自动登录的凭据验证单次执行并释放临时客户端。接口清单、实测与保留协议边界见 [SCHOOL_INTERFACES.md](SCHOOL_INTERFACES.md)。

## 同步约定

- 普通重复请求合并并共享完成结果，不同请求排队。强制刷新单独排队，确保作业提交后的刷新不会复用提交前的请求。
- `selectSemester(waitForRefresh: false)` 等待学期选择持久化后返回，内容同步继续由原同步队列执行并报告状态，避免课表导航被后台内容加载阻塞。默认调用仍等待完整刷新。
- 冷却按账户、学期和同步类型隔离。部分失败不记入成功冷却；全部内容失败返回错误。
- 网络学堂每次 HTTP 请求保留 15 秒连接、30 秒接收超时；全局同步与包含逐课程排课请求的课程目录不再叠加 90 秒/30 秒总期限，以免截断正在恢复或仍有进展的操作。同步队列等待底层操作结束再启动下一个请求。目录弹窗刷新有 20 秒展示等待期限。错误保留本地缓存，可重试。
- 切学期、登录和退出登录会使旧操作失效。API 返回后、事务写入前后检查操作有效性，防止迟到结果回填。
- 当前是逻辑取消：底层 HTTP 请求可能仍完成，但其结果不得写入失效作用域。物理请求取消尚未贯通整个 API 客户端。
- 课程、作业和通知按成功返回的服务端快照对齐；请求失败不清空缓存。课程文件的已下载记录保留，未下载且已移除的远程条目清理。
- `school_list_loader.dart` 校验通知／作业的总数并在需要时续页；文件满额时扩大 size。缺失数组、分页无进展、达到读取上限或文件丢行均返回失败，避免将不完整列表用于同步删除。
- `CourseCatalogRepository` 共享同学期的有效请求，事务内更新课程、退课索引和时间戳。所有使用者已失效的请求不得被新刷新复用；账户作用域变化重新创建仓储。
- `CourseInfo.timeAndLocationLoaded` 区分排课元数据请求失败和成功空数组。失败保留旧排课并缩短目录重试间隔至一分钟；成功空数组才清除旧排课。
- 每类课程内容最多同时同步三门课程，避免学期课程较多时无限并发。
- API 文本字段由 `decodeHtmlEntities` 按 HTML5 实体规则解码一层，保留字面尖括号与未知实体；`decodeHTML` 继续处理学校特有的乱码前缀。数据库版本 7 一次性修复旧缓存作业标题中遗留的实体，不改动成绩、提交内容或历史学期数据范围，也不要求重新联网。正文 HTML 继续交给专门的内容解析与渲染路径。

文件路径、迁移与下载发布语义见 [FILE_STORAGE.md](FILE_STORAGE.md)。

## 界面与交互边界

- `AppFont` 管理内置霞鹜文楷 GB 屏幕版的 family、资源与一次性许可证注册；`AppTypography` 定义排版角色，供主题和独立文字样式共用。`LearnYApp` 声明 `zh_CN` 并使用 Flutter 官方本地化委托。
- `CourseIdentityRepository` 合并全部已缓存学期的课程原名及当前账号的图标、简称、颜色偏好，保留按学期避重与颜色持久化。`CourseIdentityScope` 将不可变身份索引提供给所有路由；`StudyPalette` 按课程 ID 取颜色，`CourseSeal` 按同一身份绘制课程图形，普通调用方不再拼接图标编号与课程名。课程整理草稿显式传入同一身份模型，不影响其他入口；跨账号重新加载时不展示上一账号的索引。`StudySurface` 封装表面光影及按压区域，不引入背景模糊、逐帧布局或新的动画库。
- 设置分组、行内边距和控制项布局由 `settings_rows.dart` 统一管理；`AppearanceMenu` 使用 `MenuAnchor`，独立持有菜单触发器焦点，区分鼠标关闭与键盘返回。页面继续负责偏好持久化与失败反馈；自动登录摘要和详情复用同一状态快照。
- `ContentLayout` 用实际分配给页面的宽度计算边距，不改写窗口级 `MediaQuery`。`ReadingWidth` 只约束阅读宽度；根详情页按窗口宽度布局。页面中的分栏由局部 `LayoutBuilder` 决定。
- `AppShell` 保留同一 `PageView` 和分支导航器，缩放窗口不重建浏览状态。窄屏使用 `NavigationBar`，顶层页面支持触控翻页；点击导航直接切换并可打断正在进行的滑动。宽屏使用侧栏，详情浏览不参与主页面滑动。
- 手机 `Scaffold.extendBody` 让内容与壁纸延伸到悬浮导航下面；`NavigationBar` 保留原生焦点、语义、提示和点击行为，常驻标签隐藏。`ShellNavigationProgress` 在外壳范围传递分页器的真实小数页位置，更新只驱动导航透镜绘制；路由提交与页面状态仍归分页器和 GoRouter。拖动直接跟随，显式分支跳转只平滑移动指示，不让中间页面依次触发路由。`FrostedNavigationSurface` 单独负责有界模糊、明暗材质和弧面边缘；折射网格按尺寸与位置缓存，通过 `StudyLightScene.paintMesh` 复用壁纸取景，不逐帧截屏。`shell_layout_metrics.dart` 管理导航留空与拖拽遮挡高度；列表使用 Scaffold 注入的底部 inset，避免重复计算。系统栏只在壁纸或视口变化时采样上下边缘，不逐帧读回像素。
- `AppToast` 委托 `ScaffoldMessenger` 管理提示生命周期；`AppActionSheet` 在窄屏使用底部弹层、宽屏使用对话框；作业提醒使用锚定菜单。`SwipeToRead` 统一负责列表的已读操作：手机仅未读项左滑，桌面单个按钮，子卡片不再重复放置已读控件。回调必须返回 `Future<void>`，组件负责等待、防重复与失败反馈，列表数据决定项目是否移除。详情页的状态切换独立保留。
- `AnimatedDataList` 用 Flutter 的 `SliverAnimatedList` 惰性构建数据列表，只保存呈现所需的条目快照和身份；数据写入不等待动画。移除项保留手势状态并淡出收拢，新增项展开，初次加载直接呈现，空态等退出完成后出现。`ReadActionFeedback` 独立于行的生命周期，按列表范围合并最近的已读操作与撤销回调；8 秒无新操作后收起，悬停、键盘焦点及辅助导航保留操作时间。列表筛选或学期变更重建对应反馈范围，避免撤销入口指向旧范围；失败才使用错误提示。
- 作业总览从纯展示分组函数生成逾期、本周、下周、稍后和完成分组；筛选状态随学期重置，详情返回保留滚动位置。提交状态由 `HomeworkSubmissionController` 和协调器负责，界面负责编辑、确认和草稿退出提示；成功回执等待用户主动返回，不用定时关闭模拟完成。
- 作业总览与课程详情均组合 `AssignmentListItem`，共用结果、截止时间、输入方式及窄屏布局；`resolveHomeworkGradeDisplay` 只解释学校成绩值，提醒动作单独封装。课程详情原有的小字号成绩布局、状态判断和百分制颜色阈值已删除。分组折叠由作业页持有，不改变数据库或分组函数。
- `SwipeToRead` 管理阅读状态操作、防重复和撤销，通知长按菜单复用同一次操作；文件的完整菜单由文件模块负责，底层阅读状态继续走 `LearningDataActions`。弹出菜单位于应用顶层，避免 Flutter 对选中项的 `ensureVisible` 穿过嵌套导航而影响主页面位置。
- `showFileActionMenu` 统一首页和文件列表的长按／右键菜单，`FileAssetActions` 合并文件准备和分享请求，等待下载验证发布后才调用系统服务；详情使用同一分享动作。`FileTypeIcon` 统一文件图标和语义，`FileTypeMark` 仅适配行内尺寸。`AppToastHost` 可以在异步操作前捕获稳定的提示宿主，页面或条目移除后不再读取失效的行上下文。
- 课程工作台偏好与远端课程数据分离，保存失败保留草稿。排序既支持拖拽，也提供明确的前移、后移操作；详情、文件与搜索使用 `push` 保留来源上下文。
- 课程网格使用原生 `SliverGrid`，按课程 ID 的 `findChildIndexCallback` 保留跨行重排时的元素身份。`CourseDragSource` 以实际指针类型选择 Flutter 的即时或延迟识别器：鼠标移动即拖动，触控长按启动；两条路径共用排序草稿。抓取偏移用于拖影定位，实际指针用于插入判定。`CourseDragAutoScroller` 在边缘滚动后通知页面于布局完成后重新判定落点，指针无需持续移动。尺寸仅在拖动开始时读取，拖影单独重绘，停止拖动的重复回调不重复发布状态。
- 桌面课程编辑菜单锚定省略号或右键位置，图标和简称编辑仍使用独立编辑弹层。逐项前移/后移供键盘等输入使用；鼠标可一次拖到任意位置。
- `CourseGridDelegate` 独立管理每行几何，课程网格按实际文字与统计测量每行高度，卡片与拖影使用同一结果。测量缓存按课程 ID 保存，签名覆盖标题、统计、字体、宽度和字号等输入，重排不重复测量未变化的文字；移除课程时清理缓存。课程详情读取同一课程偏好，简称与官方名同时可辨认。
- 同步呈现区分未运行、进行中、部分成功和整体失败。部分警告显示为待更新项，不再统一标成红色整体失败；状态面板保留最近更新时间与未更新项目，日常界面不显示异常堆栈。真实 API 故障仍以响应为依据，不因 UI 改善而宣称网络问题已解决。
- 文件总览通过 `/files` 注册为根页面，首页文件按钮与设置中的课程文件入口可达。未读、收藏与下载管理保持各自作用域。
- 搜索控制器管理查询代次和学期语料缓存。失败语料按 Future 身份清除，旧失败不能清掉新的同学期请求；错误与空结果分别呈现。结果分组菜单执行实际筛选，不按估算行高跳转。返回全部结果时恢复其原有滚动位置。
